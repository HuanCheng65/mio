# koishi-plugin-mio

不是聊天机器人，是群友。

澪（みお）是一个 Koishi 插件，用大语言模型驱动一个拟人化的 QQ 群成员。她不会有求必应，不会每条消息都回复，大部分时候只是安静地看着聊天记录。碰到感兴趣的话题才搭两句，觉得没什么好说的就沉默——就像群里那个在线但不怎么说话的人。

设计她的时候有一个很简单的出发点：群聊机器人最大的问题不是不够聪明，是太像机器人。抢着回复、每条必应、说话像客服——哪怕用了最好的模型，一开口就知道不是人。澪想解决的是这个问题。她的核心不是「能做什么」，而是「什么时候选择不做」。

## 她怎么看群

每个开启的群都有一条只追加的事件流：群友的消息、撤回，OneBot 群里还有禁言和表情回应。每条消息有一个固定编号（m1、m2……），永远不会重排。图片在录制时就存到本地，之后原样发给模型看，不再先转成文字描述。

发给模型的上下文就是这个群自己的一条 log：她看到的每一批消息、她每一步的思考和工具调用、工具的结果，按顺序追加，写进去就不再改。这样前缀稳定，提示缓存能一直命中。

## 什么时候醒

她不是每条消息都去看。消息流安静一小段时间（默认五秒）后才醒，一直刷屏的话最多等一会儿也会醒；被 @、被叫名字、或者有人回复她的消息，会更快醒。醒来时把这段时间的新消息一次看完，决定要不要做点什么。很久没看群的话，她会知道这些消息是「现在才看到」的。

## 她能做什么

醒来之后她用工具做事，一次唤醒最多几步（默认六步）：

- **say**：说话，可以引用某条消息、@ 某人。长消息像打字一样拆开发。
- **react**：给消息贴表情回应（只有 OneBot 群有）。
- **sticker**：从自己收藏的表情包里找一张合适的发。
- **repeat**：跟着复读。
- **recall / person / remember**：翻自己的小本本、看看对某人的印象、记下点什么。
- **search / find_source**：拿不准的事去搜一下，或者查一张图的出处。

什么都不做也是一种选择，而且是最常见的那种。发送有防刷屏护栏（最短间隔、每小时上限、没人接话时连发上限），只防失控，什么时候开口由她自己判断。

## 记忆

澪的记忆是一个本子，里面是她自己写的第一人称笔记：关于某个人的事实和印象、群里发生的事和梗、关于她自己的（说过的话、答应过的事）、收藏的表情包。每条笔记记着出处的消息编号，回想时能核对原话，不会凭空「记得」；有些放在心里，对方不提就不主动提。矛盾不打标记，她直接改写原笔记，把前后变化写进去。

每批新消息到来时，和这批话题相关的笔记标题会「隐约浮现」在她眼前；想细想再用 recall 展开。

### 睡前整理

log 长到一定程度（默认十万 token），或者群里安静到缓存快要过期时，她会睡一觉：把这一段 log 收成一份群速写和一份交接，带上最近几十条消息，开始新的一段。旧段留在数据库里作记录。

## 群模式

群开关存在 Koishi 的 channel 表上，用指令切换（需要 4 级权限，在群里发）：

| 指令 | 澪的状态 |
|------|----------|
| `mio.off` | 不录制，不看 |
| `mio.record` | 只录制，不醒；她不知道这段时间发生过什么，醒来才看到 |
| `mio.on` | 正常看群、说话 |
| `mio.shadow` | 照常思考、记笔记、睡觉，但发出去的话被拦下，她以为自己说了（调试用） |
| `mio.mute` / `mio.unmute` | 只录制不醒，她知道自己被静音了：进入和解除时 log 里各有一条通知 |

OneBot 群里如果澪被 QQ 禁言，log 里会有禁言通知，禁言期间她说话的工具会直接告诉她发不出去。

其他指令：`mio.status` 看各群的模式、模型、log 大小和发送限制；`mio.sleep` 让她现在就睡前整理；`mio.reload` 重新读取提示词；`mio.tokens` 看 token 用量。

## 控制台

Koishi 控制台里有一个澪的页面：

- **模型配置**：供应商、embedding、搜索压缩、agent 模型，以及按群覆盖的 agent 模型。配置坏了也能从这里修好。
- **提示词**：人设、环境说明、说话提醒、睡前整理。在这里改的存数据库，保存后下一次请求就用新的；没改过的跟着插件 `data/` 下的文件走。
- **记忆**：按群浏览她的笔记，按类型、关于谁、文字筛选，点开看出处原话；还能看每次睡前整理写下的群速写和交接。
- **运行统计**：token 用量、缓存命中率，按用途和模型分开看。

## 架构

```
src/
├── agent/        # 新运行时：事件流、log、工具、记忆笔记、睡前整理、提示词
├── console/      # 控制台接口：配置、提示词、记忆浏览、token 统计
├── runtime/      # 群模式和开关指令
├── perception/   # 消息标准化
├── pipeline/     # 唤醒防抖
├── delivery/     # 拟人化发送
├── llm/          # 供应商、token 统计、搜索压缩用的调用
├── memory/       # embedding、搜索压缩提示词
├── search/       # 多源搜索 + 结果压缩
├── platform/     # QQ 官方 / OneBot 的平台差异
└── emoji/        # QQ 表情表
```

## LLM 支持

agent 模型需要支持工具调用和图片：OpenAI 兼容接口（DeepSeek 等）或 Anthropic Messages API。笔记的 embedding 需要一个 OpenAI 兼容的 embedding 模型。搜索结果压缩可以用任意供应商，包括 Gemini。

## 配置

```yaml
botName: 澪
botAliases: [みお, 小澪]

providers:
  - id: deepseek
    name: DeepSeek
    type: openai
    apiKey: sk-...
    baseUrl: https://api.deepseek.com

memory:
  embedding: { providerId: openai, modelName: text-embedding-3-small }

search:
  enabled: true
  searxngBaseUrl: http://localhost:18080
  compression: { providerId: deepseek, modelName: deepseek-chat }

agent:
  model: { providerId: deepseek, modelName: deepseek-flash, maxTokens: 4096, cacheTtlMinutes: 240 }
  personaFile: mio-agent.md
```

完整的配置项和默认值见 `src/config.ts`。

## 开始使用

```bash
yarn
yarn build
```

作为 Koishi 插件加载，配好供应商和 agent 模型，然后在群里发 `mio.on`。

## 关于人设

`data/persona/mio-agent.md` 定义了澪这个人，`data/agent/` 下是环境说明、说话提醒和睡前整理的说明。这些文件是种子：在控制台「提示词」里改过的版本存在数据库里，优先于文件。

你可以改人设来创造完全不同的角色，但整个系统的行为逻辑——沉默优先、慢热、选择性参与——是围绕「正常群友」这个前提设计的。如果你想做一个有求必应的助手，这个插件可能不太适合。
